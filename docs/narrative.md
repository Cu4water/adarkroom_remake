# 剧情规范

本文档规定故事讲什么、怎么不用文字讲出来、不得不用文字时怎么写、线索怎么控制。**本文档包含结局剧透。**

标注：**已定**是制作人确认过的；**建议**是 AI 提出、还没有确认的；**待定**必须由制作人决定。剧情是制作人的领域：AI 可以起草、整理、检查，但定稿权在制作人（见 `docs/dev_guide.md` 第 1.2 节）。

---

## 1. 主题内核（已定）

原版的情绪线是**孤独 → 匮乏 → 共谋 → 反转**。重制版保留这条线。

原版最有力的地方是机制和主题绑在一起：你把流浪者召进村子，分配他们砍柴、打猎、下矿，最后修好飞船自己走掉。到结尾玩家才意识到自己的身份，回头再看，前面那些"高效分配工人"的操作都变了味道。**机制让玩家成了共犯，结局再把这层意思揭开。**

任何剧情内容都要能回答：它在这条情绪线的哪个位置，为它服务还是在稀释它。

---

## 2. 故事方向

### 2.1 已定

- **揭露**：玩家其实是主导地位的流浪者。
- **四个群体**：流浪者（仆从地位）、流浪者（市民地位）、野生动物、流浪者（舰队）。各自的视觉风格见 `docs/art.md` 第 7 节。
- **外星合金拼飞机**是一个"认祖归宗"的仪式。
- **坠毁战舰**拿回来以后，一周目里只能用来手动熏肉，对一周目的玩家来说并不划算。它的搭建器到二周目才开放。这一点用来加深揭露的后劲。
- **建造者**是玩家建立的第一段关系：她要花好几分钟从发抖、喃喃自语，到愿意帮你盖房子，而不是一句话之后就变成一个功能标签页。
- 玩家角色是沉默的"你"。

### 2.2 建议

- **二周目的情绪目的是"同样的事，读出不同的意思"**：一周目里看不懂的村民台词，二周目突然读懂了。二周目不是"更快地再玩一遍"。
- **坠毁战舰要"不划算，但让人忘不掉"**：带一点说不出的怪，例如村民操作不了，只有你能用，它对你有某种反应。这条暗示必须能被发现，也能被解释过去（"大概是玩法设定吧"）。
- **二周目"不需要村民"的材料**：不能只是便利，否则就是"转生继承特权"。可以框成"主导阶层一旦掌握了技术，就不再需要仆从"：用了它，村民离开或消失，营地重新变得空荡。它是一面镜子，不是奖励。

### 2.3 待定

- 主线大纲、结局（一个还是多个）、二周目的具体内容
- 建造者的过去和最终去向
- 和原版设定（沼泽老者、不朽流浪者、舰队信标）保留到什么程度
- 游戏名称

大纲确定之前，AI 不写新的剧情节点，只做第 6 节的占位和移植。

## 3. 揭露与线索预算（已定）

线索太多，揭露就会从"原来如此"变成"果然如此"；太少，又没人注意到。

- 每条指向真相的线索有一个 id，先在 `content/design_budget.tres` 登记它在一周目里最多出现几次，再在事件数据的 `clues` 字段里引用。`design_lint` 会检查未登记的线索和超预算。
- 挑两条主线，其余埋深。主线的选择待定。
- 线索不只是文字。势力风格、音乐动机、物件、某个机制只有你能用，都算线索，都要登记。非文字的线索暂时手动登记在本节下面的表里，等检查工具支持后再转进数据。

| --- | --- | --- | --- |
| （待制作人确定） | | | |

- 每条线索都要可以被合理地解释过去。
- 测试版用本地遥测记录每条线索的暴露时间，再找测试玩家看他们在什么时候猜到真相。预算靠数据调，不靠感觉。

## 4. 无字叙事

### 4.1 原则（已定）

**重制版尽可能不使用任何文字。** 原制作组用极少的文字传达孤独、匮乏和共谋；重制版把这份克制推得更远，让玩家从画面、光、声音和自己的动作里感受到同样的东西。

- 能用非文字表达的，一律不用文字。
- 必须用文字的，要写明为什么非文字做不到，并计入文字预算（4.4）。
- 文字少了，留白就更大，玩家自己读出来的意思才是他们记得住的。

### 4.2 叙事载体（已定，按优先级）

1. **世界的变化本身**：新出现的东西就是叙事节点。门外亮起来、角落里多了一团人影、窗外多了一处火光。
2. **光**：照得到什么、照不到什么（见 `docs/art.md` 第 5 节）。
3. **声音**：风、火、呼吸、脚步、远处的斧头声，以及不含可辨词语的人声（低语、叹气、哼唱）。见 `docs/audio.md`。
4. **人物的姿态和动作**：发抖、蜷缩、站起来、伸手要柴、摇头。
5. **物件和环境叙事**：柴堆的根数、货架上的毛皮、熄灭的吊灯、墙上的痕迹。
6. **玩家自己的动作**：生火、添柴、开门。动作的手感和反馈本身就是叙事。
7. **文字**：最后的手段，见 4.3。

不用：讲解背景的过场动画、旁白、任务日志、百科词条、对白、物品名称的标签。

### 4.3 什么时候可以用文字

| 场合 | 状态 |
| --- | --- |
| 标题和 logo | 已定可以 |
| 设置、存档、退出这类系统菜单 | 已定可以，尽量少 |
| 制作人员名单、授权声明 | 已定可以，开源许可和署名要求必须有文字 |
| 无障碍模式下的字幕和描述（默认关闭） | 待定 |
| 叙事上无法用画面和声音表达、而且"文字本身"有意义的极少数时刻 | 待定，每一处都由制作人单独批准 |

除此之外，正式画面里不出现文字。

### 4.5 叙事节拍

模拟层的 `narrate(key)` 发出的不是"一句要显示的话"，而是一个**叙事节拍**：发生了一件值得玩家感受到的事。表现层决定怎么演它。`strings.csv` 里的句子只是这个节拍的说明，用在调试台和无障碍模式里，正式画面默认不显示。

每个节拍都要有非文字的表现。第一章的节拍和建议的表现：

### 4.6 怎么检查

- 截图验收时问一句：把屏幕上所有的字遮住，玩家还能知道发生了什么吗？
- 测试玩家在没有任何文字的情况下，能说出建造者经历了什么、村子发生了什么。
- 人物的话：制作人决定 NPC 说话时在头顶显示字幕，字幕跟着"哔哔啵啵"的合成人声逐字出现（`NpcSpeech` + `Babble`，见 `docs/audio.md`）。这是 4.3 的例外，每一句都登记在 4.4 的表里。动作仍然要能独立讲清楚她在干什么，字幕只是补上她说了什么。

## 5. 文风

本节适用于按 4.3 允许出现的文字，以及 `strings.csv` 里作为节拍说明的句子。

### 5.1 规则（已定）

- **短句**。一句话说一件事。叙述句一般不超过 20 个字。
- **句号断奏**。用句号，不用感叹号，少用省略号和问号。
- **具体的动作和感官**，不解释情绪，不下结论。写"陌生人在发抖"，不写"陌生人看起来很害怕"。
- **多数句子省略主语**，玩家是沉默的"你"，尽量不写出"你"。
- 建造者用"她"。村民、流浪者一般不写名字。
- 叙述里不出现数字，库存和数量由画面表达。
- 中文全角标点。

### 5.2 禁用的词

手游和放置游戏的奖励语汇会立刻破坏基调。下面这些词不出现在给玩家看的文本里：

> 恭喜、获得、奖励、特惠、限时、暴击、觉醒、狂欢、辉煌、传说、史诗、满分、成就、解锁、升级、战力、经验值、属性、加成、收益、离线

需要表达"拿到了"的时候，写具体的东西（"陷阱里有东西：毛皮"），不写"获得毛皮 ×1"。

### 5.3 范例

| 好 | 不好 | 原因 |
| --- | --- | --- |
| 火光从窗口漏出去，落进外面的黑暗里。 | 火光照亮了四周，温暖驱散了寒冷！ | 感叹号；在解释效果 |
| 一个衣衫褴褛的陌生人跌进门，倒在角落里。 | 一位神秘的陌生人来到了你的营地。 | "神秘"是结论，不是描写 |
| 她只是发抖。 | 屋子太冷，建造者无法工作（需要温度 ≥ 2）。 | 把规则写成了说明 |
| 陷阱里有东西：毛皮。 | 获得毛皮 ×1！ | 奖励语汇、数字 |

### 5.4 术语（已定）

| 用 | 不用 | 说明 |
| --- | --- | --- |
| 流浪者 | 漫游者 | 原版中文包两种混用，这里统一 |
| 建造者 | 建筑工 | |
| 陌生人 | 神秘人 | 建造者恢复之前的称呼 |
| 外星合金 | 异星合金 | |

新的术语先加进这张表（以后迁进设定库），再写进文本。

### 5.5 建造者的说话方式（建议）

参考原版（网页版和移动版共有的建造者台词，移动版的语气）定下来的写法。只管语气，不搬移动版独有的台词（见第 6 节）。

- **自然、平实、短**：一句不超过二十来个字，照平时人说话的节奏来，有需要才断开（参考"我能做陷阱。外头兴许还有活着的野兽。""货车好了。能多拉些木头。"）。不要每句硬切成四五字两截的电报腔，也不说大道理、不演硬汉嘴硬。
- **只谈眼前和手边的事**：火、木头、风、屋子、工具、林子。她的心思在眼前处境和能做的活上，不背生存常识，不生硬点名物件来凑数。
- **主动给，不开口要**：她提议、报告做好了什么，不向主角讨东西，也不道谢。
- **身体的实情少提、自然带过**：只有真的发生时才漏出来（比如屋里太冷时"太冷了。手不听使唤。"），不刻意自我解说或诉苦。
- **不问主角问题，很少说"你"**，不发号施令；最多一句平淡的叮嘱（"外头冷，出去捡柴别走太远。"）。
- **不提自己的过去**，不评价主角，不透露真相线索。她的来历和去向待定（2.3），套话里一律不碰。
- **口语、朴素**：不用成语堆砌和书面腔，不用感叹号；不说数字，不解释规则（"太冷了。手不听使唤。"，不写"温度不够没法建造"）。
- **套话按解锁分组**：新的一组跟着玩家新打开的东西走（例如出过门以后才说林子里的事），不提前说到玩家还没见过的东西。

## 6. 原版文本的使用

- 授权和发行性质还没有最终确定。在此之前，正式版本的剧情文本以原创为准。
- **Web 版（`adarkroom_old`，MPL-2.0）的文本**可以作为占位，用于迁移机制时先跑通流程。AI 用原版文本做占位时，在交付说明里列出这些键。`strings.csv` 里移植自原版的节拍说明，用 `adarkroom_old/lang/zh_cn/strings.po` 的官方中文译文（制作人要求）。
- **移动端独有的文本**（护身符、伐木时的闪字、出发前的"奴隶"独白、陨石独白等，属于 Amir Rajan 的增补）不使用，也不作为占位。
- 重写时不逐句翻译原版。原版的作用是参考结构、节奏和文风。
- 原版剧情和碎片叙事的整理见过往对话记录；需要时由 AI 从 `adarkroom_old/script/` 和 `adarkroom_old/lang/zh_cn/strings.po` 重新抽取。

## 7. 事件的写法

事件的数据结构见 `docs/architecture.md` 第 3.8 节，写作规则如下（已定）：

- **每个选择都有代价**：至少有一个选项需要付出东西，或者可能失去东西。
- **选项之间真的不同**：方向相反的选择不能得到同样的结果。原版之外的反面例子：处决小偷和放走小偷都拿到同一个特质。
- **不白给**：不出现"一次送 100 木头"的大礼包。经济要由玩家的规划驱动，不由运气驱动。
- **损失是一件能读出来的事**：小偷、瘟疫、野兽都以事件呈现，玩家要能从画面和声音里看出失去了什么（货架空了一格、少了一处窗外的火光）。
- **事件是世界里的一个情境，不是一个对话框**（已定方向，具体表现逐个事件设计）。例如乞丐：门口站着一个人，伸着手。玩家把毛皮递过去，或者关上门。选项就是玩家能对世界做的动作，代价就是玩家手里看得见的东西。
- 每个选项在表现层要有对应的动作和物件。设计一个事件时，先写出每个选项"玩家具体做了什么"，写不出来的选项不做。
- 事件数据里的文本键（`event.<事件 id>.<场景 id>`、`event.<事件 id>.<场景 id>.<选项 id>`）只作为节拍说明，用在调试台和无障碍模式里，正式画面默认不显示。
- 写完数据跑 `design_lint`，`false_choice`、`same_reward`、`free_lunch`、`clue_over_budget` 都不能有。

## 9. 工作流程

1. 制作人给出或确认大纲、这一段要传达什么、用到哪些线索。
2. AI 先写出每个节拍和选项的非文字表现（第 4.5 节的表），交给制作人确认。
3. AI 起草事件数据和节拍说明，说明放进 `strings.csv`，在交付说明里列出这些键并标明是草稿。需要真正显示给玩家的文字，按 4.4 单独申请。
4. AI 跑 `design_lint` 和文本检查，对照第 4、5 节自查，列出用到的线索和预算余量。
5. 制作人改稿、定稿。
6. 定稿的文本，AI 不再改动措辞。发现问题时提出来，由制作人决定。
