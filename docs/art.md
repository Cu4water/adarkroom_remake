# 美术规范

本文档规定画面看起来应该是什么样：风格、色彩、光照、2D 人物、势力风格、UI、特效和后处理。模型怎么做、怎么导出见 `docs/modeling.md`。

标注：**已定**是制作人确认过的；**建议**是 AI 提出、还没有确认的，可以先按它做，但不能当成定论；**待定**必须由制作人决定后才能做正式素材。

---

## 1. 风格定位（已定）

- **风格名称**：风格化手绘 PBR（Stylized Painterly PBR）。
- **参考方向**：《漫漫长夜》《看火人》《双城之战》室内场景的笔触质感。
- **三条原则**：
  1. **克制与留白**：延续原版"少给信息、逐步揭示"。不堆高饱和度特效和花哨 UI，让光影和物件本身承担叙事。
  2. **手绘触感 × 真实光影**：剪影和表面保留水粉、油画的大笔触；光照、阴影、体积氛围走真实物理逻辑，突出冷暖对比。
  3. **光即信息**：光源必须来自场景里看得见的实体（火堆、火把、提灯、门缝的天光）。光照范围和强度直接映射模拟层的状态。

路线图里"低分辨率渲染 + 调色板量化 + 抖动"的方案已被本风格替代，不再使用。

## 3. 色彩（已定）

整体是**低饱和暖棕 × 灰蓝/橄榄绿**的对比基调，让暖橙色的火光成为画面的绝对焦点。

| 区域 / 材质 | 色调 | 参考色（线性空间） | 说明 |
| --- | --- | --- | --- |
| 上部抹灰墙 | 暖米黄 / 赭灰 | `(0.34, 0.24, 0.17)` → `(0.60, 0.47, 0.35)` | 大笔触扫刷，局部剥落露出红砖 |
| 下部墙裙 | 灰蓝绿 / 黛青 | `(0.075, 0.135, 0.135)` → `(0.19, 0.28, 0.26)` | 世界坐标高度约 `0.86m ~ 0.92m` 处不规则的手绘分界 |
| 宽木地板与桌面 | 暖棕 / 蜂蜜木 | `(0.16, 0.088, 0.042)` → `(0.48, 0.285, 0.138)` | 拼板独立倒角，承接火光的暖色反光 |
| 屋梁与门窗外框 | 深胡桃木 | `(0.07, 0.038, 0.018)` → `(0.24, 0.135, 0.065)` | 框定空间边界，压住画面四角 |
| 门板漆面 | 做旧橄榄绿 | `(0.08, 0.12, 0.055)` → `(0.25, 0.31, 0.14)` | 搭配深色横向木档与铁件 |
| 工作台与窗格 | 褪色灰蓝 / 青绿 | `(0.06, 0.11, 0.17)` → `(0.20, 0.30, 0.40)` | 和暖木色、火光形成冷暖平衡 |
| 剥落露砖 / 工具箱 | 暗陶红 | `(0.18, 0.055, 0.032)` → `(0.48, 0.18, 0.105)` | 小面积点缀 |
| 火焰与炭火 | 琥珀金 → 深橙红 | 核心 `(1.0, 0.80, 0.28)` / 外焰 `(0.85, 0.14, 0.015)` | 不能过曝成死白，保留橙金层次 |
| 窗外暗夜 | 极暗寒夜蓝黑 | `(0.012, 0.024, 0.048)` | 衬托室内温暖，强化"外面冰冷危险" |

规则：

- 新场景的主色调先从这张表里选，需要新增颜色时在本表里登记。
- 高饱和颜色只留给光源和极少数叙事物件。
- **双色墙**：用世界坐标高度加低频噪声驱动墙裙分界线，不让多块墙体出现错位接缝。
- **玻璃**：不用噪点重的抖动半透明，统一用平滑混合透明（Godot Alpha Blend）加菲涅尔反射。玻璃不接受灯光、不出高光光斑，映出火光靠窗玻璃的倒影（见 5.6）。

## 4. 材质（已定）

- **基础色**：大块水粉、油画笔触，柔和色块过渡（同色系 2 到 3 档明暗），不要照片级的高频杂色。
- **缝隙压暗**：墙角、木梁交接、家具底部和木板缝隙叠加柔和的 AO 乘法压暗，系数 `0.35 ~ 0.45`。
- **粗糙度**：

| 材质 | Roughness |
| --- | --- |
| 抹灰墙、石材、木炭、织物、毛皮 | `0.85 ~ 0.96` |
| 做旧木材、木地板、木家具 | `0.72 ~ 0.85` |
| 做旧铁器、工具箱 | `0.55 ~ 0.68` |
| 搪瓷、旧黄铜、玻璃 | `0.08 ~ 0.45`，克制的高光，用来捕捉火光 |

- **凹凸**：只用低频柔和的笔触高度，强度 `0.05 ~ 0.18`，不出现刺眼的细沙噪点。

## 5. 光照

### 5.1 实体光源原则（已定）

- 室内**不启用任何通电照明**。天花板的旧搪瓷吊灯保持熄灭，作为文明衰退的环境叙事。
- 暗室的全部照明以**火堆**为唯一主光源：
  - **主火焰光**：暖橙 `(1.0, 0.46, 0.13)`，在火焰中心偏上，投射主要的动态阴影。
  - **低位炭火光**：深红橙 `(1.0, 0.20, 0.035)`，贴近炭床，勾勒石块、地板缝和柴火底面。
  - **火光反弹补光**：低功率、大半径、无阴影的暖色补光，模拟火光经过土墙和木顶的二次反弹，保证前景和角落轮廓可读，但不破坏火堆投影的方向。
  - **窗外**：只保留极弱的寒夜底色，在窗台外侧叠一点暖色外溢，呼应 `builder.light_spills`（"火光从窗口漏出去，落进外面的黑暗里"）。
  - **体积雾**：密度极低，只用来烘托火堆周围的暖晕，不能让画面发灰或出噪点。
- 其他场景沿用同一原则：先确定场景里有哪些实体光源，再布光。不允许为了"看清楚"加一盏没有来源的灯。

### 5.2 光照即信息闸门（已定）

火越旺照得越远。物体看不看得清取决于光能不能照到它。还没到揭示时机的东西放在光照不到的地方，或者在 Blender 里放进 `90_Later_Reveals` 集合，由表现层在合适的时候显现（见 `docs/modeling.md`）。

### 5.3 暗室的状态映射（已定）

表现层只订阅 `SimEvents` 的信号，不直接改模拟状态。

| 模拟状态 | 信号 | 画面 |
| --- | --- | --- |
| 火灭（`DEAD = 0`） | `fire_changed(0)` | 火焰和火光全灭，全黑。开场就是这个状态，只有风声 |
| 闷烧（`SMOLDERING = 1`） | `fire_changed(1)` | 只有炭床自己发红，照不出火塘，室内漆黑 |
| 摇曳（`FLICKERING = 2`） | `fire_changed(2)` | 小火苗晃动，光只照到火塘和一圈石头 |
| 燃烧（`BURNING = 3`） | `fire_changed(3)` | 正常火焰、少量火星，照亮火堆和周围一米左右的地板和墙根，柴堆在光的边上，门和角落还在黑里。生火之后就是这一档 |
| 熊熊燃烧（`ROARING = 4`） | `fire_changed(4)` | 最大火焰、活跃火星，火光经墙和屋顶反弹，整间屋子才亮起来 |
| 建造者状态（`-1 ~ 4`） | `builder_changed` / `temperature_changed` | 见第 6.2 节：从门口跌进来的模糊人影，随等级和室温变清楚、不再发抖，最后站到火边替你添柴。待做：她来了以后角落出现铺位，帮忙以后围裙、工具和待造的东西逐步出现 |
| 木头库存 | `store_changed` | 柴堆一共 14 根，按门槛摆：木头不少于 100 时是满的，每跌过一个门槛少一根（门槛见 `presentation/room/woodpile_view.gd`） |
| 其他库存与建造 | `store_changed` / `building_changed` | 待做：货架上的毛皮、布料、罐子随库存出现 |

相邻两档火势之间的照明差别故意拉得很大，"看得见多少"本身就是火势的读数。数值在 `presentation/room/fire_rig.gd` 的表里。火塘是开放的，没有烟罩和烟道（制作人确认删掉）。

### 5.4 引导用的光（已定）

建造者去砍柴时门外发光，吸引玩家去点门。这道光必须是世界里的光（门缝里漏进来的天光），**不能**是脉动的描边、高亮或图标。这种引导整个游戏里尽量少用，用多了就是换了皮的感叹号。

### 5.5 阴影与抗锯齿（建议）

- **火光不烘焙**。火堆的光每一档亮度不同、一直在抖、火灭了要全黑（5.2、5.3），人物、门、柴堆还会动，烘焙的光照和阴影跟不上这些变化。Godot 的 LightmapGI 阴影遮罩只支持平行光，不支持火堆这种点光源。以后真有不变的光源（例如固定的天光），再考虑只给它烘焙。
- **火光的阴影要软、分辨率要够**。真实的火焰有二三十厘米宽，影子本来就是虚的：`KeyLight` 的 `light_size = 0.25`、`shadow_blur = 3.5`。窗框离火三米多，光又是斜着照到墙上，一个阴影像素会被拉成一长段，影子边缘起阶梯状的锯齿。所以阴影图集的第一象限只放一盏灯（`atlas_quadrant_0_subdiv = 1`），让火光独占四分之一张图集，分辨率是默认分法的两倍，总显存不变。不要靠把图集加到 16384 来解决，那要多占约 1 GB 显存。
- **抗锯齿按设备自动选**（`presentation/common/graphics_quality.gd`）。独显用高档（TAA + 2 倍 MSAA，软阴影高质量，阴影图集 8192）；核显在 1440p 以内用中档（TAA，软阴影中等质量，图集 4096）；其余设备、非 Forward+ 渲染器用低档（FXAA，软阴影高质量，图集 4096）。进场景 4 秒后开始看帧时间，平均低于 50 帧每秒持续 3 秒就降一档，只降不升。调试版按 F8 轮换档位对比画面。
- 软阴影的采样噪点靠 TAA 抹匀，MSAA 只管几何边缘、管不到阴影。低档没有 TAA，用更高的阴影过滤质量顶上。

### 5.6 窗玻璃的倒影（建议）

- **玻璃不接受灯光**（`shaders/window_glass.gdshader`，unshaded）。光滑的玻璃会把点光源反射成一个圆光斑，看起来像窗上贴了个鸡蛋；火光和门外那道冷光都不该在玻璃上出现光斑。
- **夜里窗玻璃是一面暗镜子**（`presentation/room/window_reflection.gd`）：映出的是屋里的火、屋梁、建造者，屋里越亮倒影里的细节越清楚，火小时只映出火堆附近，火灭了就什么都没有。平面倒影用"视锥模式"，算法移植自 [V-Sekai/godot_planar_reflection](https://github.com/V-Sekai/godot_planar_reflection)（MIT，版权声明保留在文件开头，发行时要写进授权声明）：一台相机在窗外正对玻璃，近裁剪面落在玻璃上，窗户那面墙和窗外的东西自动不进倒影。
- 反射率取真实玻璃的 `0.04`，斜着看按菲涅尔增强。色调映射会把暗部提得很亮，反射率再大，倒影就像一扇通往另一间屋子的门。
- 倒影分辨率是屏幕高度的 1/4、0.35、1/2（低、中、高档）；窗户不在画面里时不渲染。
- **第二章天亮以后倒影消失**：外面比屋里亮，玻璃上看不见屋里。第二章的舞台调 `WindowReflection.fade_to(0.0, 秒数)`。
- 门上的玻璃只去掉了光斑，不做倒影（门会转动，倒影要跟着重算，目前不值得）。

## 6. 3D 人物

### 6.1 形式（已定）

人物采用与场景同源的**风格化手绘 PBR 3D 建模 + 骨骼动画**：造型以厚涂立绘为参考，表面使用与暗室一致的三段线性色带水粉笔触与缝隙 AO 压暗，不用自发光，让火光真实扫过人物并投下阴影。骨骼与基础动画复用开源 CC0 人形骨架与动作库。

### 6.2 建造者（已定，参考 `Art/characters/builder_2d_standee.png`）

- 二十多岁到三十出头的女性，风霜、疲惫，面容克制素雅，情绪主要由兜帽阴影、姿态和光来表达。
- 深邃尖角的橄榄褐连帽披肩与多层绕颈围巾，凌乱碎发从兜帽下垂落半遮眉眼，保留神秘感。
- 做旧灰蓝帆布工装围裙、皮革交叉肩带与双层皮革工具带，挂着工具袋、木槌、盘绕麻绳、暗陶红柄生锈铁钳，配宽松工装裤、缠布露指手套与翻领系带皮靴。颜色呼应暗室墙裙、工作台与露砖。
- 右手配可显隐的劈柴（`Builder_HeldLog`），添柴时在柴堆边弯腰拾起，抱回火塘边塞进火里。
- 现在的做法（已有）：3D 建模（`Art/scripts/build_builder_model.py`）+ 65 根标准人形骨骼与 13 条开源 CC0 动作（Quaternius Universal Animation Library 1 & 2），导出为 `remake/assets/builder/builder.glb`。刚进门时通过着色器 `blur` 参数压暗去饱和、边缘柔暗，呈现火光边缘一团模糊人影，随恢复等级和室温逐步清晰。
- 屋里靠墙放着一把木椅（`remake/assets/chair/chair.glb`，见 `docs/modeling.md`）。她缓过来以后把它搬到火边，之后一直坐在上面。
- 第一章的动画状态机（`presentation/room/builder_pose.gd` 定连线，`builder_rig.gd` 搭成 `AnimationTree`，`builder_figure.gd` 排动作）：

| 模拟等级 | 她平时停在 | 进入这一级时演的过渡 |
| --- | --- | --- |
| COLLAPSED | 侧躺在地蜷成一团（`lying`），膝盖收到身前，双臂交叉抱着胸口，脸朝着火，喘得急、轻微发抖 | 门被撞开，抱臂站在门口，踉跄（`stagger`）走进屋，转向火，仰面瘫倒（`collapse`），再慢慢侧过身蜷起来 |
| SHIVERING | 坐在火边的椅子上（`sitting`），埋着头，抖得最厉害 | 撑地站起来（`get_up`），哆嗦着走到墙边，弯腰拿起椅子（`pickup`），抱着走到火边（`walk_carry`），放下，绕到前面坐下（`sit_down`） |
| SLEEPING | 在椅子上睡着，呼吸慢而深，头歪向一边 | 发抖慢慢停下，头低下去 |
| HELPING | 坐在椅子上，人影清楚 | 站起来（`stand_up`），站着说她能帮忙，再坐回去。第一次找她说话：她抱着板子（`walk_carry`）绕开火塘走到主角跟前一臂外，递过去，说一句，再走回去坐下 |

  搬椅子：站在椅子前一步弯腰扣住椅子，直起身时椅子先离地、再收到怀里；抱着走时托在坐面底下，跟着两手正中晃，椅子腿高过膝盖；放下时站在椅背后一步、半蹲着落地，落地有一声闷响；放好以后贴着椅子侧面绕到前面坐下（`BuilderProps`、`BuilderPose.seat_layout`）。
  帮忙以后：模拟说她添柴时，从椅子上站起来，走到柴堆弯腰拿一根（`pickup`），抱着走回（`walk_carry`），在火塘边塞进火里（`feed`），再坐下；屋里太冷时抱臂哆嗦一阵；柴不够时摇头。冷颤、呼吸、歪头和摇头是叠在骨骼动画上的程序化动作（`BuilderRig.overlay`）。她说话时头顶出字幕（见 8.1）。

### 6.3 人物建模与着色规则（建议）

- 剪影清楚，在暗处只看轮廓也能认出是谁。
- 面部保持克制、不画夸张五官表情，依赖兜帽阴影、姿态和火光传达情绪。
- 用色从第 3 节的色表里取，与所在场景共用同一套手绘笔触与 AO 压暗语言。
- 骨骼统一使用 65 根标准人形骨架，方便后续村民、流浪者复用同一套开源动作库。

## 7. 势力风格

制作人的方案是参考《赛博朋克 2077》的四种时代风格（实用主义、刻奇、新军阀、新刻奇），给四个群体各定一套视觉风格：

| 群体 | 对应的风格 | 状态 |
| --- | --- | --- |
| 流浪者（仆从地位） | 实用主义 | 已定方向，形状语言和材质待定 |
| 流浪者（市民地位） | 刻奇 | 已定方向，细节待定 |
| 野生动物 | 新军阀 | 待定。建议改为覆盖在其他风格上的一层有机侵蚀，而不是独立的一套 |
| 流浪者（舰队） | 新刻奇 | 已定方向，细节待定 |

规则：

- **先只做一套**，验证副本拼装出来好不好看、重复感强不强，再做第二套。先做哪一套待定。
- **舰队风格不能在一周目早期清楚地出现**，否则会提前泄露"玩家就是主导地位的流浪者"。玩家后来用外星合金拼的飞机，风格要逐步向舰队风格靠拢，而不是一开始就一样。风格本身也是线索，算进线索预算（见 `docs/narrative.md`）。
- 每套风格定稿时，在本节补上：形状语言（剪影、比例、重复的几何元素）、主材质、主色、标志性的道具。

## 8. UI 与字体

### 8.1 UI（已定）

- **正式画面尽可能不出现文字**（见 `docs/narrative.md` 第 4 节）。没有文字日志、按钮文字、物品名称、数值。数值和叙述文字只在调试台里看。
- 禁止：脉动描边、感叹号或红点、进度条、飘字、数字滚动、闪烁的"新"标记、成就弹窗。
- UI 放进世界里：柴堆的根数就是木头的库存，门外的光就是"现在可以出去"，货架上的东西就是你有什么。
- 抽象图标也尽量不用。能用世界里的物件表达的，不画成图标。
- 画面要能独立讲清楚发生了什么。审核截图时把它当成一部默片来看。
- 系统菜单（设置、存档、退出）可以有文字，用同一个 `Theme`，克制、低对比。
- 可交互物件的高亮：只在"当下点了能成、准星正对着"时，在物件上叠一层很淡的暖光，边缘稍亮（`interact_glow.gdshader`）。不描边、不呼吸、不闪，平时完全看不见。人物身上只留一点边缘光，底光会让人像发光的鬼影。

制作人要求的例外（已定，不再扩大）：

## 9. 特效与后处理

### 9.1 特效（已定）

- 火焰和火星用风格化着色器和粒子（`presentation/room/shaders/`），跟随火势变化。
- 特效服从"光即信息"：不为好看加没有来源的光效、拖尾、屏幕震动。

### 9.2 后处理（已定）

- Godot 的 `WorldEnvironment` 用 `AgX` 色调映射，对应 Blender 预览的 `AgX`（Medium High Contrast）。
- `Glow` 很轻，只作用于火焰和火星这类高亮的发光体。
- 体积雾可选，强度很低。
- 所有舞台共用同一份环境配置（放在 `presentation/common/`），2D 立绘和 3D 场景经过同一套后处理。

## 10. 审核流程

1. AI 产出：Blender 渲染图或 Godot 运行截图，固定机位，至少一张全景、一张近景。暗室这类有火势变化的场景，至少截"火灭"和"燃烧"两档。
2. 和 `Art/scenes/*_preview.png` 这类已确认的参考图并排对比，在交付说明里写出差异。
3. 制作人确认后，素材才算完成。没确认的素材可以进游戏，但要在交付说明里标"待审"。
4. AI 生成的图片可以用作概念参考和立绘底稿。进正式版的素材要经过制作人确认，并在素材清单里注明来源。
